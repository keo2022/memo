# 우리 결혼 준비 앱

둘이 함께 쓰는 결혼 준비 앱입니다. 화면 아래 탭 3개로 나뉩니다:

- **메모**(왼쪽): 공통으로 작성/열람하는 메모장. 메모1, 메모2 처럼 여러 개 만들 수 있음.
- **메인**(중앙, 첫 화면): 결혼식·상견례 같은 날짜를 등록해두면 D-day로 보여주는 홈 화면.
- **엑셀**(오른쪽): 원래 이 앱의 전부였던 기능 — 시트별로 탭을 만들고 셀에 값이나 `=SUM(A1:A3)` 같은 수식을 넣는 표.

여러 명이 같은 데이터를 보고 써야 해서, 데이터는 **클라우드에 올린 백엔드 서버**에 저장됩니다.
앱은 그 서버에 HTTP로 접속합니다 (오프라인 단독 실행 불가, 서버가 켜져 있어야 함).

## 구조

```
backend/   Node.js + Express API 서버. DB는 같은 서버 안의 SQLite 파일(backend/data/db.sqlite)에 저장.
frontend/  React Native + Expo 앱.
           네비게이션: 하단 탭(메모 / 메인 / 엑셀) → 각 탭 안에 스택(src/navigation/RootNavigator.tsx).
           frontend/src/db/repository.ts 가 백엔드 API를 호출합니다.
```

- **시트(Sheet)**: 카테고리 (예: 가계부, 운동일지)
- **탭(Tab)**: 시트 안에 여러 개 만들 수 있는 표
- **셀(Cell)**: 값 또는 `=`로 시작하는 수식. 지원 함수는 `SUM`, `AVERAGE`, `MAX`, `MIN`, `COUNT`, `ROUND`, `IF`, 연산자는 `+ - * / ()` 와 비교 연산자 `> < >= <= = <>` (참이면 1, 거짓이면 0)
- 앱이 접속할 서버 주소는 `frontend/.env`의 `EXPO_PUBLIC_API_URL`로 설정합니다. 클라우드에 배포한 뒤 이 값을 배포된 주소로 바꿔주세요.

## 백엔드 로컬 실행

```powershell
cd backend
npm install
npm run dev   # http://localhost:4000 에서 실행
```

별도 DB 서버(Postgres 등)는 없습니다 — 데이터는 `backend/data/db.sqlite` 파일 하나(SQLite)에 저장됩니다.
`better-sqlite3`(네이티브 모듈)를 쓰며, `npm install` 시 대부분 플랫폼용 미리 빌드된 바이너리를 자동으로 받습니다
(빌드 도구가 없어도 됨). **Node.js 20 이상**이면 되고 별도 실행 플래그도 필요 없습니다.

서버를 옮길 때는 파일 하나만 복사하면 됩니다:
```
sqlite3 db.sqlite "PRAGMA wal_checkpoint(TRUNCATE);"   # wal 내용을 본 파일에 합침 (서버 정지 후)
# db.sqlite 를 새 서버로 복사 → DB_PATH 를 그 경로로 지정 → 서버 시작
```

클라우드에 배포할 때 영구 디스크(volume)를 마운트했다면, `DB_PATH` 환경변수로 그 안의 경로를 지정하세요
(예: 볼륨이 `/data`에 마운트됐다면 `DB_PATH=/data/db.sqlite`). 안 정해주면 서버 코드 폴더 안의 `data/db.sqlite`를 쓰는데,
이 위치가 영구 디스크가 아니면 재배포할 때마다 데이터가 사라집니다.

## 0. 사전 준비

1. [Node.js](https://nodejs.org) **20 이상** 설치 (npm 포함) — 이미 설치돼 있다면 생략.
2. 무료 [Expo 계정](https://expo.dev/signup) 생성 (APK를 클라우드에서 빌드하기 위해 필요)

## 1. 개발 중 미리보기 (선택)

APK를 빌드하기 전에 PC에서 바로 화면을 확인하고 싶다면 Expo Go로 미리 볼 수 있습니다.

```powershell
cd frontend
npm install
npm run start
```

터미널에 뜨는 QR 코드를 폰의 **Expo Go** 앱으로 스캔하면 실행됩니다.
(이때 백엔드 서버가 켜져 있어야 하고, `frontend/.env`의 `EXPO_PUBLIC_API_URL`이 그 서버 주소를 가리키고 있어야 합니다.)

## 2. 설치 파일(APK)로 빌드하기

QR 스캔 없이, 파일을 폰에 내려받아 탭 한 번으로 설치하는 방식입니다.

```powershell
cd frontend
npm install -g eas-cli   # 최초 1회만
eas login                # Expo 계정으로 로그인 (최초 1회)
eas build:configure      # 최초 1회: 프로젝트를 Expo 계정에 연결 (프롬프트에 Enter로 진행)
eas build -p android --profile preview
```

- 빌드는 Expo의 클라우드 서버에서 진행되며 보통 5~15분 정도 걸립니다.
- 완료되면 터미널과 [expo.dev](https://expo.dev) 대시보드에 **다운로드 링크(QR 포함)** 가 나타납니다.
- 폰에서 그 링크를 열어 `.apk` 파일을 다운로드한 뒤, 알림창에서 탭하면 설치됩니다.
  - 처음 설치 시 "출처를 알 수 없는 앱 설치 허용"을 묻는 안내가 뜨면 허용해주세요.
- 이후로는 이 APK가 폰에 남아있는 독립 앱이라, PC를 켜지 않아도 실행됩니다.

### 앱을 업데이트하고 싶을 때

코드를 수정한 뒤 위 `eas build -p android --profile preview` 명령을 다시 실행하고,
새로 나온 APK를 다시 설치(덮어쓰기)하면 됩니다. 데이터는 백엔드 서버 쪽에 남아있으므로 유지됩니다.
(단, `app.json`의 `android.versionCode`를 올리지 않아도 재설치는 되지만, 관례상 배포할 때마다 1씩 올려주는 것이 좋습니다.)

## 3. 사용 흐름

앱을 켜면 **메인 탭**(가운데)이 먼저 뜹니다. 아래 탭으로 메모 / 메인 / 엑셀을 오갑니다.

### 엑셀 탭

1. 시트 목록 화면에서 시트 추가 (예: "가계부")
   - 항목 오른쪽의 점3개(⋮)를 누르면 이름 변경 / 삭제 가능 (삭제하면 그 안의 탭·데이터도 함께 삭제됩니다)
   - 항목을 길게 눌러서 위아래로 드래그하면 순서를 바꿀 수 있습니다
2. 시트 클릭 → 그 시트의 첫 번째 탭이 바로 열립니다 (탭이 없으면 추가 화면). 오른쪽 위 목록 아이콘으로 전체 탭 목록(순서 변경, 이름 변경/삭제)을 볼 수 있고, + 아이콘으로 바로 새 탭 추가 가능
3. 그리드가 나오면, 셀을 탭하면 값/수식 입력 가능 (체크 포맷 열은 O/X/해제 선택 버튼이 뜹니다)
   - 예: A1에 `10`, A2에 `20`, A3에 `=SUM(A1:A2)` 입력 시 30 표시
   - 행 번호(1, 2, 3...)나 열 머리글(A, B, C...)을 길게 누르면 그 위치의 위/아래(또는 왼쪽/오른쪽)에 행·열을 끼워 넣거나, 그 행/열 자체를 삭제할 수 있습니다 (맨 끝 행/열에서 "아래에"/"오른쪽에"를 선택하면 맨 끝에 추가하는 것과 같습니다. 최소 1개의 행/열은 남아있어야 해서, 1개만 남았을 땐 삭제 옵션이 나오지 않습니다). 이미 병합된 셀 범위 "안쪽"에 삽입/삭제하면 병합 범위가 같이 늘어나거나 줄어들고, 수식이 참조하던 셀 주소도 자동으로 조정됩니다
   - 열 머리글을 짧게 탭하면 그 열의 포맷(기본/체크/숫자)과 **너비**를 설정 가능. 열 너비는 기본적으로 그 열에서 가장 긴 값 기준으로 자동 맞춰지고, +/- 버튼으로 수동 조정하거나 "기본 크기로" / "내용에 맞게 자동 조정"으로 되돌릴 수 있습니다
   - 셀을 길게 누르면 셀 병합 설정 가능 (같은 값을 여러 행/열에 반복 입력하지 않아도 되도록). 병합되면 왼쪽 위 셀의 값만 유지됩니다

## 여러 명이 같이 쓸 때 (구현됨)

- **편집자 이름**: 앱을 처음 켜면 이름을 한 번 물어봅니다(로그인 아님, 기기에 저장). 시트 목록 상단 칩에서 언제든 바꿀 수 있고, 모든 셀 수정에 이 이름이 기록됩니다.
- **동시 수정 충돌 처리**: 내가 화면에 띄운 뒤 상대가 같은 칸을 먼저 고쳤으면, 저장할 때 "충돌" 창이 떠서 [상대 값 유지] / [내 값으로 덮기]를 고르게 합니다 (마지막 저장이 조용히 덮어쓰지 않음).
- **변경 기록**: 탭 화면 오른쪽 위 시계 아이콘 → 최근 셀 변경 목록(누가·언제·무엇을 → 무엇으로). 셀별 가장 최근 변경은 "이 값으로 되돌리기"로 되돌릴 수 있습니다.
- **자동 새로고침**: 탭을 열어두면 15초마다 상대방 변경을 가져옵니다. 화면을 아래로 당겨 새로고침(pull-to-refresh)도 됩니다. 편집 중(입력창·창이 열려 있을 때)에는 건너뜁니다.

데이터: `cells` 테이블에 `updated_at` / `updated_by` 컬럼이 추가되고, `cell_history` 테이블이 새로 생깁니다 (서버가 시작할 때 기존 DB에 자동 반영). SQLite는 WAL 모드로 켜집니다.

## 메인 탭 (D-day)

- `events` 테이블: `{ id, title, date('YYYY-MM-DD'), order_num }`. API: `GET/POST /api/events`, `PUT/DELETE /api/events/:id`.
- 오늘 이후 중 가장 가까운 날짜를 큰 D-day 카드로, 나머지는 아래 목록으로 보여줍니다. 카드/행을 누르면 수정·삭제.
- 날짜는 년/월/일 숫자 입력 (별도 날짜 피커 라이브러리 안 씀).

## 메모 탭

- `memos` 테이블: `{ id, title, content, order_num, created_at, updated_at, updated_by }`. API: `GET /api/memos`(목록, 본문 제외), `GET /api/memos/:id`(본문 포함), `POST /api/memos` `{title}`, `PUT /api/memos/:id` `{title?, content?, baseUpdatedAt?}`, `DELETE`.
- 셀과 같은 방식의 동시편집 충돌 처리: `baseUpdatedAt`이 서버보다 오래됐으면 409 + 상대 내용 반환 → 앱에서 [내 내용으로 덮어쓰기] / [상대 내용 불러오기] / [취소].
- 편집 화면은 15초 폴링 + pull-to-refresh (편집 중이면 건너뜀), 저장은 헤더 "저장" 버튼 / 하단 바.

## 빌드 시 유의

프론트엔드에 네이티브 모듈이 추가됐습니다: `@react-native-async-storage/async-storage`(편집자 이름 저장), `@react-navigation/bottom-tabs`(하단 탭). Expo Go 미리보기는 그대로 되지만, **APK는 `eas build`를 다시 돌려야** 반영됩니다.
